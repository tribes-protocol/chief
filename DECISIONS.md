- 2026-08-28 — **A shell guard tests USABILITY, never EXISTENCE.** Three separate defects this week were one defect: the check asked whether a thing was THERE when the only question that matters is whether the next line can USE it. A decision a NAMED GUARD already enforces is not carried — it lives at its guard, and a second copy here is a second thing to keep true; that struck the reactive mandate (`lint:reactive` plus the `clippy.toml` interval ban), the three-binary split (`no-ts-cli-stub`, `chiefd-workspace-location`), beacond-as-the-only-address (`no-chiefd-url-stamp`), assigned-work-is-a-message (`mail-demand-reads-one-table`) and the refusal taxonomy (`refusal-taxonomy`). And every entry that survived NAMES ITS PINNING TEST: an entry that cannot name one is not a decision that binds the code, it is doctrine, and doctrine belongs in `AGENTS.md` or nowhere. Where `AGENTS.md` already carries a rule — the organization model, the operator wake lease, placement-is-derived — it is not duplicated here either.
- 2026-08-25 — Who runs is decided only by the launch-intent fence, and the fence is written only by explicit decisions. The durable per-person fence is the sole authority; it fails closed, and an absent, unreadable or foreign fence authorizes NOBODY but the CEO — `Fenced(∅)`, never "no fence". The verbs that write it are each an explicit, named-person decision: an operator or head start; a person's BIRTH STATE, where hiring or seeding an ACTIVE person grants their fence in the same transaction while a benched one stays fenceless and stopped by its own definition, and creating a department fences its head and every explicitly named active initial seed; and DELIVERY, where a message to a person grants the recipient intent through the mailbox write itself — the send IS the wake. The verbs that never write it: pause clears the whole subtree's fences transactionally; resume restores department state only and starts NOBODY, not even the head; a transfer preserves intent untouched. No pane is ever spawned inside any of these transactions — the reconciler converges to the fence. Pinned by `an_absent_ledger_fences_everyone_but_the_ceo` (`launch_intent.rs`), `create_launches_an_active_initial_staff_seed_with_the_department`, `create_commits_complete_initial_staff_and_their_launch_fences_in_one_transaction`, `hiring_a_benched_person_records_no_launch_fence`, `resume_after_pause_leaves_launch_intent_absent_and_spawns_nobody`, `transfer_preserves_launch_intent_and_never_touches_supervision` (`org_ops.rs`), and `ManagerDelegatesOnDelivery.test.ts`.
- 2026-08-25 — Who stops: everybody settles, except the root, which never does. A person with no loop and no goal attached releases their pane; blocked work parks, and the unblocking party's message re-wakes them. The CEO is the exception and holds a PERMANENT lease: it accrues no idle clock and never parks, because a parked CEO is an unreachable company. That narrowed an earlier position under which the root settled like anybody else, and the narrowing is the operator's — "CEO can never go to sleep". Note what it is NOT: the CEO is still not protected from anything but the structural verbs, and a park was never "acting on" the CEO in the sense the organization model protects against. Pinned by `the_ceo_holds_a_permanent_lease_and_never_parks`, which replaced `the_ceo_settles_and_parks_like_everybody_else`, plus `the_settle_window_is_the_operators_five_minutes`, `the_settle_clock_starts_when_the_agent_says_it_went_quiet_and_not_before` and `a_routine_idle_park_waits_for_the_settled_lease_and_is_capped_in_flight` (`activity/tests.rs`).
- 2026-08-25 — Business logic lives in Rust; TypeScript relays, presents and applies input, and never decides. If a TypeScript path is making a decision rather than relaying one, it is in the wrong place. The TypeScript surface is large enough to look like a peer implementation, so "fix it in TS" is the reflex for every bug, and that is what re-creates the cross-language race this rule ended. Pinned by `MandateFence.test.ts` (`apps/web/test/`).
- 2026-08-25 — Desired state flows down; observation never flows up. chiefd holds DESIRED state, the client projects it into tmux, and the client never reports back what it saw. The one upward channel is an agent reporting facts about ITSELF (`/v1/org/activity/agent-state`), which is a different thing from the actuator reporting what it observed in a pane. An agent debugging "chiefd does not know the pane died" reaches for an upward channel every time, and four observation-conditioned code paths have been deleted for it. The downward half is pinned by the launch-intent tests in `converge_apply::cycle`; **the no-upward-report half has NO PINNING TEST and that is a recorded gap, not an oversight** — a route-surface assertion could not be made to discriminate a legitimate downward read from an upward report, so this entry is the record until one can.
- 2026-08-25 — `chief-cli` and `chiefd-core` may not link each other, so the placement algorithm exists on both sides and the two answers are reconciled by a shared GOLDEN FILE, never by a shared crate. Two implementations of one algorithm reads as obvious duplication to delete; the golden file is the only place the answers can meet, and removing it silently un-pins tmux placement. Pinned by `backend-tmux-boundary.test.mjs` (whose "neither side depends on the other" clause IS the no-link rule, with its own negative self-test), `the_golden_topology_is_what_this_client_computes_from_the_golden_roster` (`chief-cli/placement/tests.rs`) and `the_golden_roster_is_the_body_this_backend_serves` (`chiefd-core/runtime/roster/tests.rs`).
- 2026-08-25 — Durable state is typed, normalized and single-writer, in SQL only — one database per company, no file backend, no dual-write, no JSON columns, no generic document read/write routes for product consumers, and no caller-supplied revision or write-precondition. There is no migration framework: a retired schema object is dropped idempotently and a newly declared column is added at open, which is what keeps existing companies alive across releases and looks like dead generality until an upgrade bricks one. The sole named carve-out is the 2PC crash journal's plan blob, which is a journal and never an authority. Pinned by `normalized_schema_forbids_json_columns` (`schema.rs`), `every_generic_document_route_is_unmounted` (`docstore_http_surface.rs`), `two_implementation_stores.rs` and `sql-only-state.test.mjs`.
- 2026-08-25 — Absence has two polarities and no reader may collapse them. A document never written reads as EMPTY; a store that cannot be REACHED is a REFUSAL — never "no mail", "no lease", "nobody staffed". Each store and operation declares its polarity in a sealed registry, where omission is a compile error. The sharpest instance, and the reason this is not pedantry: a fault in the trust store answers `503 identity-store-unavailable`, never `403`. "Fail closed" reads as satisfied by any refusal, but "could not look" and "looked and found nothing" are different answers a client acts on differently — one seven-second stall answered 403 to every caller and froze a company for two hours. Pinned by `fail_safe_value_decode_of_unreadable_launch_intent_denies_everyone` (`polarity.rs`) and `an_absent_ledger_fences_everyone_but_the_ceo`.
- 2026-08-25 — There is no lock anywhere on the write path. Serialization is beacond's single-writer admission plus one writer actor per company, and reads run on a bounded READ-ONLY connection pool where a write fails at the SQLite layer by construction rather than by discipline. Any concurrency bug invites "add a lease"; two leases have already been re-created under new names and deleted again. Pinned by `single_writer_admission.rs` (`chiefd-daemon/tests/`).
- 2026-08-25 — No deadline may ever end an attempt. The actuator never gives up on a person chiefd wants up: it backs off from 500ms to a 10-second ceiling and holds that ceiling for ever. A duration that SPACES attempts is allowed; one that STOPS them is not. Watchdogs, stale-starter sweeps and give-up-after-N are the reflex fix for a stuck person, and the previous crash-loop hold sealed its own exit and left live companies permanently dead. Pinned by `a_person_who_keeps_crashing_keeps_being_retried_for_ever` and `the_backoff_grows_exponentially_and_stops_at_ten_seconds` (`actuate/crash_loop/tests.rs`), plus `crash_loop_never_gives_up.rs` against a real tmux.
- 2026-08-25 — The company IS the directory. Identity is a hash of the canonical directory path, defined once; the rendezvous file a command follows is a POINTER, never an authority, and pid liveness plus a health probe decide; slugs are display names with no uniqueness. beacond is only the box-wide presence registry, and its own database is the single sanctioned exception to "every durable fact is a row in the company's database" — a table inside the database you are trying to locate cannot tell you where it is. Pinned by `the_company_key_separates_two_directories_and_is_stable_for_one` (`rendezvous.rs`), `adoption_needs_all_three_facts_never_two`, `a_rendezvous_copied_from_another_directory_is_not_this_directorys_daemon`, `an_absent_or_unreadable_rendezvous_is_no_daemon_rather_than_a_failure` (`daemon.rs`) and `two_directories_hold_two_companies_even_when_they_share_a_slug` (`beacond/store.rs`).
- 2026-08-25 — A company's tmux socket and session name are its own identity. The socket falls back to the company key and never to the shared default, and every minted session name is terminated so that no company's name can be a prefix of another's. The terminator looks like a typo to clean up: `tmux -t` falls back to prefix matching, so removing it moves an operator into the wrong company and lets one teardown kill another company's server. Pinned by `no_caller_can_fall_through_onto_the_shared_tmux_default` and `two_companies_falling_through_never_share_a_server` (`company.rs`), and `no_minted_tmux_session_name_is_a_prefix_of_another`, `no_two_companies_can_mint_prefix_related_session_names` and `every_tmux_session_mint_is_covered_by_the_prefix_rule` (`tmux.rs`).
- 2026-08-25 — A department is never headless. There is exactly one head at every instant, and a head is removed only by appointing a successor in the same transaction, with the incumbent demoted. "Fire anyone" is satisfied by succession, never by vacancy. Pinned by `a_head_with_a_successor_hands_over_and_the_department_survives` and `no_decision_refuses_and_names_the_department_and_its_successors` (`org_ops.rs`).
- 2026-08-25 — The CEO is the OPERATOR's own Pi, not a managed agent: no managed agent home, no managed session directory, no coding-agent-directory override. Every other person has exactly one create-once home, so code that assumes "look up this person's agent directory" is right nineteen times out of twenty and produces a CEO with no tools on the twentieth. Pinned by `chief_profile_uses_company_cwd_and_operator_pi_identity_without_a_managed_home` and `chief_profile_requires_the_company_identity_key_not_a_managed_home` (`converge_apply/api_host_profile.rs`), and over HTTP by `profile_route_admits_shadow_and_returns_the_camel_case_nonsecret_wire_shape`.
- 2026-08-25 — Pi is the operator's own program. chief resolves it by walking `PATH` and taking the first candidate that ANSWERS its version flag — not the first that is executable — and reports Resolved, Unusable or Absent as three distinct answers. A Pi whose interpreter is missing is executable and dead, and collapsing Unusable into Absent makes chief reinstall on every invocation behind the shadow. chief declares a MINIMUM Pi version, warned about at preflight and refused only by the upgrade verb; it does not pin one. Pinned by `a_candidate_that_does_not_answer_is_stepped_over_for_one_that_does`, `a_candidate_that_does_not_answer_its_version_flag_is_not_the_answer`, `executable_candidates_that_all_fail_are_unusable_and_named` and `absent_and_unusable_are_not_the_same_code` (`preflight.rs`).
- 2026-08-25 — Reminders are rows in the durable ledger, and they are the product's ONLY recurrence mechanism. A session-scoped loop is easy to re-add and dies silently on the first pane restart; a reminder survives a pane restart, a daemon restart and a stop/relaunch, which is the whole point and the reason the session-scoped loop was deleted forward-only. Pinned by `an_armed_reminder_is_durable_across_a_reopen` and `a_due_reminder_fires_and_rearms` (`supervision/reminders/tests.rs`), `arming_over_http_writes_the_ledger_the_dispatch_duty_reads` (`reminders_http_surface.rs`), and the reminder family in `OrganizationToolContract.test.ts`.
- 2026-08-25 — Authentication and authorization are unconditional and server-side. Every daemon run builds the auth runtime — no environment switch, no config, no dev mode, because a switch that can be off will be off. Authorization is decided by the daemon ON THE ROUTE from the authenticated caller, and any client-side check is a pre-flight in front of an authority, never the authority itself. Caller identity comes from the verified credential, never from a body field. Pinned by `an_absent_service_key_refuses_to_build` and `an_absent_operator_key_refuses_to_build_rather_than_warning` (`authn/boot.rs`), and by the `*_caller_http.rs` family in `chiefd-api/tests/`.
- 2026-08-25 — An identity key is written create-once with a syscall that REFUSES — `link(2)` returning `EEXIST` — never with an existence check followed by a write, and a surviving agent directory is ADOPTED by the next company rather than deleted. `rename(2)` is the house idiom for atomic writes and is exactly wrong here: the LAST writer wins, and a replaced anchor locks a person out permanently because nothing re-points the trust table. Pinned by `a_late_minter_never_orphans_the_key_that_was_already_enrolled` and its family, plus `a_key_left_by_a_previous_company_is_adopted_and_starts_its_person`.
- 2026-08-25 — A tool's parameters is always ONE object schema, never a union, and no argument holds an object inside an object. A union expresses branch exclusivity elegantly and a strict provider rejects the WHOLE catalog on it — the cost is not a worse schema, it is a CEO that cannot take a single turn. Pinned by `every tool a provider is shown has a top-level object schema` (`tool-surface-artifact.test.mjs`), and `no registered tool declares its top level as anyOf/oneOf/allOf` and `asks a model to build nothing deeper than one person seed` (`ToolParameterSchemas.test.ts`).
- 2026-08-25 — Pi owns provider and model metadata and reasoning effort. A pane is told no route and no appearance: chief never passes a provider or model flag, never sets the offline switch, and never freezes Pi's model metadata into a launch. Validating model ids against a chief-side list is the obvious hardening and re-creates a deleted allowlist. - 2026-08-25 — Every string chiefd composes for a launch must be representable as ONE tmux argument, and the quoting helper REFUSES anything else. That refusal is a command-injection boundary the PROMPT bends to, never the guard: a multi-line prompt is the natural thing to write, and a newline TERMINATES the nested conditional body, so half a guarded respawn executing is the false-ownership state the refusal exists for. Pinned by `a_newline_argument_is_refused_rather_than_truncated` (`control/tests.rs`) and, on the composing side, `every_published_resume_prompt_is_representable_as_one_command_argument` (`runtime/resume_prompt.rs`).
- 2026-08-25 — Only an IDLE pane is asked to start a turn. A delivery to a busy pane rides the follow-up or steer queue instead. The general "deliver a message" call looks like the right one everywhere; on a busy pane it throws inside Pi where the sender's error handling cannot see it, and the message is silently lost. Pinned by `never asks a busy pane to start a turn` and `asks for a turn only when no turn is in flight` (`QueuedDelivery.test.ts`), `re-queues a bare submission on a busy pane` (`InputRequeue.test.ts`) and `a turn in flight hands off to agent_settled instead of burning the ten-attempt budget` (`IdleResumeIsEventDriven.test.ts`).
- 2026-08-25 — Chief never puppets a live agent. No product path types text or Enter into an agent's pane — the surviving keystroke calls are mouse forwarding and copy-mode control, which are not typing. A message is DELIVERED through the mailbox and the person is woken by a targeted reconcile. Extensions load once at session start, and a pane that can prove it runs superseded code REFUSES the action naming both timestamps: adopting a deploy is a restart, and a restart is the operator's decision. Pinned by `no-typing-at-a-live-agent.test.mjs`, written for this entry because the rule had lived in one doc comment, and by `StaleExtensionRefusal.test.ts`.
- 2026-08-25 — Every person gets the Pi builtin tool floor, and a ROLE is the installed skill set. The floor is composed unconditionally at launch and never stored, so a seed naming one tool cannot amputate the rest. What differentiates a manager is exactly the installed skill — `founder`, `manager` or `worker` — reconciled to an exact set on every pass, which is WHY no tool is role-gated anywhere in the product. A role flag beside the skills is the natural design and it was tried: a flat skills link meant every role statement was contradicted by what the person could actually read. Pinned by `every_person_gets_the_whole_builtin_floor_whatever_their_seed_declared`, `composing_the_floor_does_not_write_it_into_the_person_record` and `the_role_sets_are_not_part_of_the_floor` (`converge_apply/resource_catalog.rs`).
- 2026-08-25 — The rail is required operator infrastructure, not optional display state — and the OPERATOR OWNS ITS WIDTH. An expanded-width preference is read and applied, with the product default used only when none is recorded and a readability floor below which the rail cannot draw its own headings; a fresh client applies a custom width without writing preferences back. The rail is repaired on every readable pass, indented by each department's depth in the store's tree, and re-derived per pass rather than cached. Clicking a DEPARTMENT draws a card about the unit, never a grid of that unit's live agents — the tiling version rendered each agent of a six-person unit at 42 of 129 columns and forced Pi to repaint its whole scrollback on every switch. - 2026-08-25 — Discovery has no clock. beacond never expires, sweeps or reaps a registration on a timer: removal is an explicit verb, and liveness is judged by the READER from pid plus process start time. A TTL is the reflex fix for the first stale row anybody sees and is wrong twice over — the row may belong to a company that is slow rather than dead, so deleting it makes a healthy daemon unreachable to every client, and a sweeper is a background loop the reactive mandate bans outright. Pinned by `discovery-has-no-sweeper.test.mjs`, written for this entry because the rule had lived in a module doc comment.
- 2026-08-25 — Releases are cut from every GREEN commit on the trunk, one tag per commit. The version is passed to the build rather than committed; an installed binary finds its resources relative to its own executable rather than through a recorded path; and a client refuses to DRIVE a daemon whose MAJOR or MINOR version differs, while tolerating a PATCH-level skew that would otherwise strand a company that was up before the swap. A committed version number and a recorded launcher-root pointer both look like standard practice, and the recorded-path variant alone cost two separate incidents. - 2026-08-25 — CI has ONE tier. Every workspace member gates; there is no non-gating tier and no quarantine, so a suite is either run and required to pass or it does not exist.
